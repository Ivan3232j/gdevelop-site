# Топдаун Шутер · Урок 1: Движение, прицеливание и камера

Nov 17, 2026 · @Иван Денисов

## Цель и подготовка

К концу урока дети создадут своего персонажа (танк, солдата или космический корабль), который свободно перемещается по экрану с помощью клавиатуры и плавно поворачивается вслед за курсором мыши. Мы также привяжем камеру к игроку, чтобы создать большой открытый мир для исследования.

**Главная идея урока для детей:** Разделение управления. В шутерах клавиатура отвечает только за ноги (перемещение), а мышь — только за глаза и руки (прицеливание).

**Новые понятия:** поведение Top-Down Movement (Движение сверху вниз), имитация нажатия клавиш (Simulate key press), функции координат мыши `CursorX()` и `CursorY()`, центрирование камеры.

**Подготовить заранее:**

- [ ] Создать свой проект-эталон с танком или кораблем на большой карте, чтобы дети могли «поездить» в начале урока
- [ ] Нарисовать на доске систему координат: почему спрайт должен смотреть вправо (это 0 градусов в математике GDevelop)
- [ ] Подготовить запасной спрайт персонажа (вид сверху) для тех, кто медленно рисует

## Тайминг 90 минут

| Время | Блок | Что делают дети |
| --- | --- | --- |
| 0–10 | Вход | Играют в эталон. Обсуждают, чем управление отличается от платформера и раннера |
| 10–30 | Рисуем персонажа | Спрайт в Piskel (вид сверху, **строго смотрит вправо**) |
| 30–50 | Поведение Top-Down | Добавление поведения, отключение авто-поворота, управление WASD, тест движения |
| 50–70 | Прицеливание | Событие слежения за мышью (Rotate toward position) |
| 70–85 | Камера и фон | Tiled Sprite для земли, центрирование камеры на игроке |
| 85–90 | Итог | Сохраняют проект. Вопрос: почему мы рисовали нос вправо, а не вверх? |

## Блок 1. Рисуем персонажа (10–30 мин)

Игра с видом сверху (Top-down shooter), поэтому мы смотрим на макушку персонажа, крышу танка или корабля.

1. **Создать новый проект:** разрешение **1280 × 720**, горизонтальная ориентация. В свойствах проекта включить пиксельный режим: **Scale mode (Режим масштабирования) = Nearest (Ближайший сосед)**, иначе пиксель-арт будет размытым.
2. Создать объект Sprite с именем `Player` и открыть встроенный Piskel.
3. Холст **64 × 64 пикселя**.
4. **САМОЕ ВАЖНОЕ ПРАВИЛО:** Персонаж (лицо, дуло танка или нос корабля) должен смотреть **строго вправо** (на 3 часа). В движке GDevelop угол 0° направлен вправо, а углы растут **по часовой стрелке** (90° — вниз). Если нарисовать дуло вверх, танк будет ездить и целиться боком.
5. Редактор объекта → Точки (Edit points). Здесь две разные точки, и обе ставим по геометрическому центру спрайта:
   - **Центр (Center)** — ось вращения. Вокруг неё персонаж поворачивается за мышью. По умолчанию она уже стоит по центру автоматически — проверьте, что её никто не сдвинул.
   - **Точка начала (Origin)** — «точка-кнопка», которой объект ставится на координаты X/Y. По умолчанию она в **левом верхнем углу**. Перенесите её в центр: на следующих уроках пули и взрывы будут появляться ровно в нужном месте.

**Как объяснить детям:** Center — это гвоздик, на котором крутится картинка. Origin — это ножка циркуля, которую мы ставим в точку X/Y.

## Блок 2. Поведение Top-Down Movement (30–50 мин)

Вместо того чтобы вручную программировать каждую кнопку перемещения, мы используем готовое поведение для перемещения по плоскости.

1. Открыть свойства объекта `Player` → вкладка **Поведения (Behaviors)**.
2. Добавить поведение **Top-Down Movement** (Движение сверху вниз).
3. **Критически важная настройка:** В параметрах поведения снимите галочку с **«Rotate object»** (Вращать объект). Если её оставить, персонаж будет поворачиваться туда, куда идет, а нам нужно, чтобы он смотрел на курсор мыши!
4. Оставьте управление по умолчанию включённым (галочка «Ignore default controls» / «Игнорировать стандартное управление» должна быть **снята**). **Внимание:** стандартное управление — это **только стрелки**. WASD поведение само не понимает, его добавим событиями ниже.
5. Перетащите `Player` на сцену (ближе к центру будущей карты) и запустите превью. Персонаж должен ездить на стрелках, но пока не поворачиваться за курсором.

**События 1–4 — Управление WASD:**

Мы не программируем движение заново, а «нажимаем стрелку за игрока»: поведение думает, что нажата стрелка, и само разгоняет персонажа.

| Условие | Действие |
| --- | --- |
| Клавиша `w` нажата *(Key pressed)* | `Player` → **Имитировать нажатие клавиши «вверх» (Simulate up key press)** |
| Клавиша `a` нажата | `Player` → **Simulate left key press** |
| Клавиша `s` нажата | `Player` → **Simulate down key press** |
| Клавиша `d` нажата | `Player` → **Simulate right key press** |

*(Действия Simulate … key press находятся в разделе поведения Top-Down Movement у объекта `Player`.)*

**Мини-эксперимент (2 минуты):** в настройках поведения поменяйте **Max speed** с `200` на `1000`, а потом на `50`. Каково управлять ракетой и черепахой? Верните `200` — от этого числа будем отталкиваться на уроке 3, когда враги должны быть медленнее игрока.

## Блок 3. Прицеливание мышью (50–70 мин)

Теперь свяжем поворот персонажа с курсором мыши, чтобы можно было маневрировать и отступать назад, отстреливаясь во все стороны.

**Событие 5 — Слежение за мышью:**

| Условие | Действия по порядку |
| --- | --- |
| (без условий) | 1. Выбрать объект `Player` → **Повернуть к позиции (Rotate toward position)** |
|  | 2. X: `CursorX()` |
|  | 3. Y: `CursorY()` |
|  | 4. Угловая скорость: `0` *(0 означает мгновенный поворот. Если поставить 300, башня будет крутиться плавно, как у тяжелого танка)* |

**Разбор для детей:** `CursorX()` и `CursorY()` — это встроенные радары GDevelop, которые каждый кадр считывают, над какой точкой **игрового мира** сейчас находится мышка (не экрана, а именно карты — это важно, когда камера начнёт ездить). Событие без условий (выполняется каждый кадр) приказывает персонажу постоянно обновлять свой угол поворота в сторону этих радаров.

**Мини-эксперимент (2 минуты):** поставьте угловую скорость `60`. Быстро поводите мышкой по кругу — персонаж «не успевает» за прицелом. Так в играх делают тяжёлую технику. Верните `0`.

## Блок 4. Камера и фон (70–85 мин)

Чтобы почувствовать свободу перемещения, нужен мир, который больше размера одного экрана.

1. Создать объект **Tiled Sprite** (Плиточный спрайт) с именем `Background` (нарисовать простую клетку, металл, траву или марсианский песок в размере 64 × 64 пикселя). Рисунок должен быть бесшовным: левый край стыкуется с правым, верхний — с нижним.
2. Поставить его на сцену в точку **X = 0, Y = 0**, растянуть очень широко (**3000 × 3000 пикселей**) и поставить на задний план (Z-order = -1).
3. **Центрирование камеры:** в то же самое событие без условий (где мы делали прицеливание) добавьте действие **Центрировать камеру на объекте (Center the camera on an object)** → выбрать `Player`. Перетащите это действие **на первое место**, выше поворота: сначала камера встаёт на место, потом мы считаем, куда смотрит мышь. Иначе при быстрой езде прицел будет слегка дрожать.

**Как объяснить детям:** камера — это оператор с камерой, который бежит за актёром. Актёр всегда в центре кадра, а декорации (фон) уезжают назад.

## Частые ошибки и быстрые решения

| Что видит ребёнок | Причина | Решение |
| --- | --- | --- |
| Персонаж целится боком или задом наперед | В Piskel нос нарисован не вправо (не на 0 градусов) | Открыть Piskel и повернуть рисунок стрелочками интерфейса вправо |
| Персонаж сам крутится, когда я нажимаю стрелочки | Забыли снять галочку вращения в настройках поведения | Открыть вкладку Behaviors объекта `Player` и выключить «Rotate object» |
| Стрелки работают, а WASD — нет | Стандартное управление Top-Down понимает только стрелки | Добавить 4 события «Клавиша нажата → Simulate … key press» |
| WASD не работает, хотя события есть | В поле клавиши написано `W` или русская `ц` | Выбрать клавишу из списка в окне условия (имена клавиш строчные: `w`, `a`, `s`, `d`) |
| При вращении за мышкой персонаж сильно дергается по кругу | Точка Center стоит не по центру рисунка | Зайти в «Edit points» объекта и сбросить/выставить точку Center по центру |
| Персонаж доезжает до края экрана и пропадает | Нет центрирования камеры | Добавить действие «Центрировать камеру на объекте Player» |
| Фон перекрывает игрока | Z-order фона больше, чем у игрока | Задать объекту `Background` Z-order = -1 или поместить на нижний слой |
| Персонаж уезжает с карты в чёрную пустоту | У карты нет стен | Это нормально для базового трека; стены по краям — задание для быстрых №3–4 |
| Персонаж с размытыми, «мыльными» краями | Не включён пиксельный режим проекта | Свойства проекта → Scale mode = Nearest |

## Проверка результата и задания для быстрых

**Урок пройден, если у ребёнка:**

- [ ] Персонаж свободно ездит по фону (на WASD или стрелочках)
- [ ] Нос персонажа всегда смотрит точно на курсор мыши, независимо от направления движения
- [ ] Камера держит персонажа в центре экрана, пока он едет по большой карте

**Задания для быстрых (по сложности):**

1. **Плавная башня:** Изменить угловую скорость в действии поворота с `0` на `250`. Посмотреть, как изменится управление (оно станет более «тяжелым», появится инерция прицеливания).
2. **Скорость и ускорение:** Зайти в настройки поведения Top-Down Movement и изменить параметры Acceleration (Ускорение), Deceleration (Торможение) и Max Speed (Макс. скорость). Настроить управление так, чтобы персонаж был резким или, наоборот, плавно разгонялся и скользил, как по льду. *Перед уроком 3 вернуть Max Speed около 200.*
3. **Первые препятствия:** Создать объект Sprite `Wall` (стена, ящик). Отдельного поведения «препятствие» для Top-Down в GDevelop нет — стену делаем событием: **`Player` касается (Collision) `Wall`** → действие **Разделить объекты (Separate objects)**: сдвинуть `Player` от `Wall`. Построить небольшой лабиринт и проверить, как персонаж упирается в стены.
4. **Края карты:** Обставить фон 3000 × 3000 стенами `Wall` по периметру (растянуть 4 стены вдоль краёв), чтобы игрок не мог уехать в пустоту. Дополнительно: в событие «В начале сцены» добавить действие **Enforce camera boundaries** (Ограничить камеру) с границами `0; 0; 3000; 3000` — камера перестанет показывать чёрную пустоту за краем.
