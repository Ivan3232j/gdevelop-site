# Раннер · Урок 1: Бесконечная дорога и три полосы

Oct 20, 2026 · @Иван Денисов

## Цель и подготовка

К концу урока у каждого ребёнка нарисованная им дорога бесконечно бежит вниз, а его персонаж плавно перескакивает между тремя полосами — стрелками и тапом по экрану.

**Главная идея урока для детей:** персонаж никуда не бежит, бежит мир. Это иллюзия, на которой построены все раннеры.

**Новые понятия:** Tiled Sprite (плиточный спрайт), смещение картинки, `TimeDelta()`, переменная-номер полосы, поведение Tween (плавное движение).

**Подготовить заранее:**

- [ ] Обновить GDevelop на всех компьютерах до одной версии
- [ ] Проверить, что встроенный редактор Piskel открывается (в прошлых версиях бывало чёрное окно)
- [ ] Сделать свой проект-эталон этого урока, чтобы показать результат в начале
- [ ] Нарисовать запасной тайл дороги и персонажа — для тех, кто не успеет

Рисование занимает треть урока — это нормально, своя графика сильно мотивирует. Если группа медленная, ограничьте рисование таймером и выдайте запасные спрайты.

| Время | Блок | Что делают дети |

| 0–10 | Вход | Смотрят эталон, обсуждают: кто на самом деле двигается — персонаж или мир? |

## Блок 1. Рисуем свои спрайты (10–35 мин)

Рисуем во встроенном редакторе Piskel: он открывается прямо из редактора объекта в GDevelop. Два спрайта на этот урок: тайл дороги и персонаж.

**Сначала настройка проекта (делает каждый, 2 минуты):**

1. Свойства проекта → разрешение игры **720 × 1280**, ориентация вертикальная.
2. Там же режим масштабирования — «ближайший сосед» (для пиксель-арта). Иначе увеличенный персонаж будет размытым.

**Тайл дороги — 240 × 240 пикселей = одна полоса.** Тайл повторится три раза по ширине и получится дорога из трёх полос.

1. Залить весь квадрат цветом асфальта (заливка — один клик).
2. По левому и правому краю провести тонкую полосу разметки, по 4 пикселя. Соседние тайлы сложат их в линию 8 пикселей между полосами.
3. Добавить детали: пятна, трещины, люк.

**Главное правило бесшовности — объясните детям на доске:** всё, что касается верхнего края, должно продолжаться у нижнего. Проще всего: детали рисуем только в середине, не трогая верх и низ. Иначе на дороге будет видна «ступенька» каждые 240 пикселей.

**Персонаж — 48 × 48 пикселей, вид сзади.** В сцене его увеличим в 3–4 раза. Маленький холст — быстрее рисовать, и пиксель-арт выглядит аккуратнее.

После рисования персонажа: редактор объекта → Точки → поставить **точку начала (Origin) в центр**. Без этого персонаж будет стоять не по центру полосы (подробнее в Блоке 3).

**Предупредите детей про Piskel:** он нестабилен на больших картинках (больше 600 × 600) и иногда падает при частом Ctrl+Z, теряя работу. Поэтому: холсты маленькие, сохраняем чаще, ошибки исправляем ластиком, а не десятью отменами подряд.

## Блок 2. Бегущая дорога (35–50 мин)

Дорога — это один неподвижный объект, внутри которого сдвигается картинка. Так мы получаем бесконечную дорогу из одного маленького тайла.

**Шаги:**

1. Создать объект **Tiled Sprite** с именем `Road`, картинка — нарисованный тайл.
2. Поставить его в сцену в точку (0, 0) и растянуть на весь экран: ширина 720, высота 1280.
3. Создать **переменную сцены** `Speed` = 400. Это скорость мира в пикселях в секунду.
4. Событие без условий (выполняется каждый кадр), действие: `Road` → смещение изображения по Y → **вычесть** `Speed * TimeDelta()`.
5. Запустить превью.

**Если дорога поехала вверх** — поменять «вычесть» на «прибавить». Не исправляйте молча: спросите детей, почему так вышло. Это хороший момент разобраться, что такое смещение.

**Как объяснить `TimeDelta()` детям:** это сколько секунд прошло с прошлого кадра (примерно 0,016). Скорость 400 × 0,016 ≈ 6 пикселей за кадр. На быстром и медленном компьютере дорога едет одинаково.

**Мини-эксперимент (2 минуты):** поменять `Speed` на 100, потом на 1500. Дети сами видят, что одна переменная управляет «ощущением скорости». Дальше по модулю на `Speed` завязаны и препятствия, и ускорение.

## Блок 3. Три полосы и управление (50–75 мин)

Персонаж хранит не координату, а **номер полосы** 1, 2 или 3. Координату X мы считаем из номера по одной формуле — её же потом используем для препятствий и монет.

**Формула центра полосы:** `X = Lane * 240 - 120` → полоса 1 = 120, полоса 2 = 360, полоса 3 = 600. Попросите детей посчитать на доске самим.

**Подготовка:**

1. Объект Sprite `Player` (точка начала — в центре!), поставить в X = 360, Y ≈ 1050, увеличить в 3–4 раза.
2. Добавить объекту поведение **Tween**.
3. Создать переменную сцены `Lane` = 2.

**Четыре события:**

| Условия | Действия |
| --- | --- |
| Клавиша «Влево» **только что нажата** + `Lane` > 1 | `Lane` вычесть 1; Tween позиции X игрока к `Lane * 240 - 120` |
| Клавиша «Вправо» **только что нажата** + `Lane` < 3 | `Lane` прибавить 1; тот же Tween |
| Кнопка мыши отпущена + `CursorX()` < 360 + `Lane` > 1 | как для «Влево» |
| Кнопка мыши отпущена + `CursorX()` ≥ 360 + `Lane` < 3 | как для «Вправо» |

**Настройки Tween:** идентификатор `move`, длительность 0,15 с, плавность easeOutQuad. В старых версиях GDevelop длительность в миллисекундах (150) — проверьте на своей.

**Почему тап так работает:** на телефоне касание по умолчанию считается кликом мыши. Тап по левой половине экрана — влево, по правой — вправо. На компьютере проверяем кликами мышью, на уроке 5 это заработает на телефонах без доработок. Если в вашей версии нет `CursorX()`, используйте `MouseX()`.

**Вопрос детям, который стоит задать:** почему условие «только что нажата», а не «нажата»? Дайте сначала сделать с «нажата» — персонаж улетит в крайнюю полосу за один удар по клавише. Пусть сами найдут причину: условие срабатывает каждый кадр, пока клавиша зажата.

## Частые ошибки и быстрые решения

| Что видит ребёнок | Причина | Решение |
| --- | --- | --- |
| Персонаж прыгает сразу через две полосы | Условие «клавиша нажата» | Заменить на «только что нажата» |
| Персонаж стоит не по центру полосы | Точка начала в левом верхнем углу | Перенести Origin в центр спрайта |
| На дороге видна «ступенька» | Тайл не бесшовный | Убрать детали с верхнего и нижнего края |
| Дорога едет вверх | Знак смещения | «Вычесть» ↔ «прибавить» |
| Персонаж размытый | Режим масштабирования | Поставить «ближайший сосед» в свойствах проекта |
| Плавного перехода нет или он дёргается | Tween в событии без условий, перезапуск каждый кадр | Tween только внутри событий смены полосы |
| Переход длится вечность | Миллисекунды вместо секунд | 0,15 вместо 150 (или наоборот) |
| Ничего не происходит | Опечатка `lane` вместо `Lane` | Имена переменных чувствительны к регистру |
| Piskel — чёрное окно, рисунок пропал | Сбой редактора | Сохранять чаще, меньше Ctrl+Z, перезапустить GDevelop |

## Проверка результата и задания для быстрых

**Урок пройден, если у ребёнка:**

- [ ] Дорога бежит вниз без видимых швов
- [ ] Персонаж своего рисунка стоит по центру средней полосы
- [ ] Стрелки и клики двигают его ровно на одну полосу, за край он не уходит
- [ ] Переход между полосами плавный

**Задания для быстрых (по сложности):**

1. Добавить управление клавишами A и D в те же события.
2. Нарисовать второй кадр персонажа и сделать анимацию бега из двух кадров.
3. Наклонять персонажа при переходе: Tween угла на ±15° и обратно.
4. Нарисовать траву по бокам: экран шире дороги, второй Tiled Sprite едет с той же скоростью `Speed`.
